Sort a K-Sorted Array Given an integer array where each element is at most k positions away from its sorted position, sort the array in a non-decreasing order.

Example: Input: nums = [5, 1, 9, 4, 7, 10], k = 2 Output: [1, 4, 5, 7, 9, 10] Intuition In a k-sorted array, each element is at most k indexes away from where it would be in a fully sorted array. A trivial solution to this problem is to sort the array using a standard sorting algorithm. However, since the input is partially sorted (k-sorted), we should assume there’s a faster way to sort the array.

We can think about this problem backward. For any index i, the element that belongs at index i in the sorted array is located within the range [i - k, i + k]. The main inefficiency with this approach is finding the minimum number in the range [i, i + k] at each index i. Linearly searching for it will take O ( k ) O(k) time at each index.

To improve this approach, we’d need a way to efficiently access the minimum value at each of these ranges. A min-heap would be perfect for this.

Min-heap For a min-heap to determine the minimum value within each range [i, i + k], it will always need to be populated with the values in these ranges as we iterate through the array. Let’s see how this works over the same example.

Implementation Python JavaScript Java from typing import List import heapq          def sort_a_k_sorted_array(nums: List[int], k: int) -> List[int]: # Populate a min-heap with the first k + 1 values in ‘nums’. min_heap = nums[:k+1] heapq.heapify(min_heap) # Replace elements in the array with the minimum from the heap at each # iteration. insert_index = 0 for i in range(k + 1, len(nums)): nums[insert_index] = heapq.heappop(min_heap) insert_index += 1 heapq.heappush(min_heap, nums[i]) # Pop the remaining elements from the heap to finish sorting the array. while min_heap: nums[insert_index] = heapq.heappop(min_heap) insert_index += 1 return nums Complexity Analysis Time complexity: The time complexity of sort_a_k_sorted_array is O ( n log ⁡ ( k ) ) O(nlog(k)), where n n denotes the length of the array. Here’s why:

We perform heapify on a min_heap of size k + 1 k+1 which takes O ( k ) O(k) time. Note that k k is upper-bounded by n n in this operation since the heap won’t have more than n n values.

Then, we perform push and pop operations on approximately n − k n−k values using the heap. Since the heap can grow up to a size of k + 1 k+1, each push and pop operations takes O ( log ⁡ ( k ) ) O(log(k)) time. Therefore, this loop takes O ( n log ⁡ ( k ) ) O(nlog(k)) time in the worst case.

The final while-loop runs in O ( k log ⁡ ( k ) ) O(klog(k)) time since we pop k + 1 k+1 values from the heap. Note that k k here is also upper-bounded by n n.

Therefore, the overall time complexity is O ( k ) + O ( n log ⁡ ( k ) ) + O ( k log ⁡ ( k ) ) = O ( n log ⁡ ( k ) ) O(k)+O(nlog(k))+O(klog(k))=O(nlog(k)).
